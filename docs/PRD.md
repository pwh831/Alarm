## 1. 개요

### 1.1 한 줄 요약
정해진 횟수의 **푸시업 또는 스쿼트를 카메라로 인식**해서 완료해야만 꺼지는 알람 앱.

### 1.2 배경
- "알라미(Alarmy)"처럼 미션을 수행해야 꺼지는 알람은 이미 검증된 시장이다. 기존 미션은 사진 찍기, 수학 문제, 흔들기, 걸음 수 같은 것들이다.
- 흔들기나 걸음 수 미션은 폰을 손으로 흔들어서 쉽게 속일 수 있다. 수학 문제는 몸이 아니라 머리만 깨운다.
- **전신 운동(푸시업·스쿼트)** 을 하면 심박수와 체온이 올라서 잠이 확실히 깬다. 아침 운동 습관까지 같이 만들 수 있다.
- 온디바이스 포즈 추정 기술(ML Kit Pose Detection, MediaPipe, Apple Vision)이 충분히 발전해서, 서버 없이 실시간으로 반복 횟수를 셀 수 있다.

### 1.3 문제 정의
| 사용자 문제 | 현재 대안의 한계 |
|---|---|
| 알람을 무의식적으로 끄고 다시 잔다 | 일반 알람은 버튼 한 번으로 꺼진다 |
| 미션 알람도 요령이 생기면 반쯤 잠든 채로 끈다 | 흔들기·수학 문제는 몸이 덜 깬 상태에서도 가능하다 |
| 아침 운동을 하고 싶지만 꾸준히 못 한다 | 운동 앱은 동기부여 알림만 주고 강제성이 없다 |

### 1.4 목표 (Goals)
1. 사용자가 알람이 울린 뒤 **실제로 몸을 움직여 완전히 깨어나도록** 한다.
2. 운동 인식이 **정확하고 속이기 어렵게** 만든다.
3. 운동 기록을 쌓아서 **아침 운동 습관 형성**을 돕는다.

### 1.5 비목표 (Non-Goals, MVP 기준)
- 본격적인 피트니스 코칭(자세 교정 피드백, 운동 프로그램)
- 웨어러블(워치) 연동
- 소셜 기능(친구 랭킹, 챌린지)
- 푸시업·스쿼트 외 운동 종목 (v2 이후 확장 후보)

## 2. 타깃 사용자

### 2.1 페르소나
**A. 늦잠 직장인 "민수" (29세)**
- 알람을 5개 맞춰도 다 끄고 잔다. 지각이 잦다.
- 원하는 것: 절대 다시 잠들 수 없는 알람

**B. 운동 습관을 만들고 싶은 "지은" (33세)**
- 퇴근 후엔 지쳐서 운동을 못 한다. 아침에 짧게라도 하고 싶다.
- 원하는 것: 강제로라도 매일 아침 운동하게 만드는 장치, 기록 확인

**C. 수험생 "현우" (19세)**
- 새벽 기상이 필요하지만 몸이 잘 안 깬다.
- 원하는 것: 짧고 확실하게 잠을 깨우는 방법

### 2.2 사용 환경 가정
- 침실. 조명이 어둡거나 간접 조명만 있을 수 있다.
- 폰을 바닥이나 협탁에 세워두고 운동하는 상황
- 잠옷 차림, 좁은 공간

## 3. 핵심 사용자 흐름

```
[알람 설정] → [알람 울림] → [미션 화면 진입] → [폰 거치 & 카메라 가이드]
   → [운동 수행 (실시간 카운트)] → [목표 횟수 달성] → [알람 해제]
   → [기상 확인(선택)] → [오늘의 기록 화면]
```

### 3.1 알람 설정 흐름
1. 홈에서 "+" 버튼으로 새 알람 추가
2. 시간, 반복 요일, 알람음, 볼륨, 진동 설정
3. **미션 선택**: 푸시업 / 스쿼트 / 랜덤
4. **목표 횟수 설정**: 5~50회 (기본값 푸시업 10회, 스쿼트 15회)
5. **난이도**: 쉬움 / 보통 / 어려움 (인식 기준의 엄격함, 아래 5.3 참고)
6. 저장 전에 "미리 해보기"로 인식이 잘 되는지 테스트할 수 있다

### 3.2 알람 해제 흐름
1. 알람이 울리면 잠금 화면 위에 전체 화면 알람이 표시된다
2. "미션 시작" 버튼을 누르면 카메라가 켜진다 (**알람음은 계속 울린다**. 볼륨만 조금 줄이는 옵션 제공)
3. 거치 가이드: "폰을 바닥에 세우고 전신이 보이도록 2~3m 떨어지세요"
4. 전신이 인식되면 카운트다운 3초 후 카운트 시작
5. 한 번 할 때마다 숫자 표시, 효과음, 진동 피드백
6. 목표 횟수를 채우면 알람이 꺼지고 축하 화면이 나온다
7. 사용자가 **60초간 움직이지 않으면** 알람 볼륨을 최대로 되돌린다

## 5. 운동 인식 상세 설계

### 5.1 기술 접근
- **온디바이스 포즈 추정**: 영상은 서버로 보내지 않는다 (프라이버시와 오프라인 동작 보장).
  - Android: Google ML Kit Pose Detection 또는 MediaPipe Pose Landmarker
  - iOS: Apple Vision `VNDetectHumanBodyPoseRequest` 또는 MediaPipe
  - 크로스플랫폼으로 간다면 MediaPipe로 통일하는 방안을 우선 검토
- 33개(MediaPipe) 또는 17~19개(Vision) 관절 좌표와 신뢰도를 입력으로 받아 **관절 각도 기반 상태 머신**으로 반복 횟수를 센다.

### 5.2 반복 카운트 로직 (상태 머신)

**스쿼트**
```
상태: STANDING → DESCENDING → BOTTOM → ASCENDING → STANDING(+1)

- 무릎 각도 = angle(엉덩이, 무릎, 발목)
- STANDING: 무릎 각도 ≥ 160°
- BOTTOM:   무릎 각도 ≤ 100° (난이도별로 조정)
- 엉덩이 y좌표가 실제로 내려갔는지 교차 검증
- 양쪽 다리 중 신뢰도가 높은 쪽 사용, 둘 다 있으면 평균
```

**푸시업**
```
상태: UP → DOWN → UP(+1)

- 팔꿈치 각도 = angle(어깨, 팔꿈치, 손목)
- UP:   팔꿈치 각도 ≥ 150°
- DOWN: 팔꿈치 각도 ≤ 90° (난이도별로 조정)
- 몸통 일직선 검증: angle(어깨, 엉덩이, 발목) ≥ 150° (무릎 대고 하는 푸시업은 '쉬움'에서만 허용)
- 몸이 수평에 가까운지 검증해서 서서 팔만 굽히는 속임수 방지
- 권장 카메라 위치: 측면
```

### 5.3 난이도별 기준
| 난이도 | 스쿼트 BOTTOM 무릎 각도 | 푸시업 DOWN 팔꿈치 각도 | 무릎 푸시업 |
|---|---|---|---|
| 쉬움 | ≤ 120° | ≤ 110° | 허용 |
| 보통 | ≤ 100° | ≤ 90° | 불허 |
| 어려움 | ≤ 85° | ≤ 75° | 불허 |

### 5.4 노이즈 처리
- 관절 좌표에 이동평균 또는 One Euro Filter 적용
- 상태 전이에 히스테리시스 적용 (경계값 근처 떨림 때문에 중복 카운트되는 것 방지)
- 필수 관절 신뢰도 < 0.5인 프레임은 무시하고, 연속 1초 이상이면 "몸이 잘 안 보여요" 안내

### 5.5 저조도 대응
- 화면 밝기를 자동으로 최대로 올리고 흰 배경 UI로 조명 역할을 하게 함 (전면 카메라 사용 시)
- 후면 카메라 사용 시 플래시(토치) 켜기 옵션
- 인식률이 계속 낮으면 "방 불을 켜주세요" 안내

## 6. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| **신뢰성** | 알람은 설정 시각 ±5초 안에 **반드시** 울려야 한다. 재부팅, 앱 업데이트, 방해 금지 모드, 배터리 절약 모드에서도 동작해야 한다 (최우선 요구사항) |
| **인식 정확도** | 정상 자세 기준 카운트 정확도 ≥ 95%, 오탐(안 했는데 카운트) ≤ 2% |
| **성능** | 포즈 추정 ≥ 15 FPS (중급 기기 기준), 카메라 시작부터 인식까지 ≤ 2초 |
| **배터리** | 대기 상태에서 추가 배터리 소모 거의 없음. 미션 1회(약 1분)에 배터리 1% 미만 |
| **프라이버시** | 카메라 영상은 기기 밖으로 보내지 않고 저장도 하지 않는다. 이 원칙을 온보딩에서 명확히 고지 |
| **오프라인** | 모든 핵심 기능은 네트워크 없이 동작 |
| **접근성** | 큰 글씨, 음성 안내(TTS)로 횟수 읽어주기, 색각 이상을 고려한 색상 |
| **지원 기기** | Android 10+ / iOS 16+ |

## 7. 플랫폼 제약 및 대응

### 7.1 Android
- `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM` 권한으로 정확한 알람 예약 (`AlarmManager.setAlarmClock`)
- 전체 화면 알람: `USE_FULL_SCREEN_INTENT` (Android 14부터 권한 필요)
- 제조사 배터리 최적화(삼성, 샤오미 등)로 알람이 죽는 문제 → 기기별 예외 등록 안내 화면 제공
- 미션 중 강제 종료 방지: 포그라운드 서비스로 알람음 재생 유지
- 부팅 후 알람 재등록: `RECEIVE_BOOT_COMPLETED`

### 7.2 iOS (주요 리스크)
- iOS는 서드파티 앱이 알람을 강제로 계속 울리게 하는 데 제약이 크다.
  - iOS 26+의 **AlarmKit** 프레임워크를 우선 검토 (시스템 알람처럼 무음 모드를 무시하고 잠금 화면에 표시 가능)
  - AlarmKit을 쓸 수 없는 버전에서는 Critical Alert(별도 승인 필요)나 반복 로컬 알림 + 오디오 세션 유지 방식으로 대체. 이 경우 "알람 끄기를 막을 수 없다"는 한계를 사용자에게 투명하게 안내
- 앱을 강제 종료하면 알람을 다시 울리기 어렵다 → 반복 로컬 알림으로 부분 대응

**결정 (v0.2)**: MVP는 **Android 네이티브(Kotlin) 우선 출시**로 신뢰성을 검증하고, iOS는 Swift + AlarmKit으로 뒤따라 출시한다.

- 이유: 이 앱의 핵심인 알람 스케줄링과 카메라 포즈 추정은 어느 방식이든 네이티브로 작성해야 한다. 크로스플랫폼으로 아낄 수 있는 부분은 목록·설정·통계 같은 비교적 쉬운 화면뿐이다.

| 영역 | Android (MVP) | iOS (2단계) |
|---|---|---|
| UI | Jetpack Compose | SwiftUI |
| 알람 | `AlarmManager.setAlarmClock` + 포그라운드 서비스 + `BOOT_COMPLETED` | AlarmKit |
| 카메라 | CameraX | AVFoundation |
| 포즈 추정 | ML Kit Pose Detection (정확도가 부족하면 MediaPipe로 교체) | Vision 또는 MediaPipe |
| 저장소 | Room | SwiftData |

- 반복 횟수 판정 로직(관절 각도 상태 머신)은 플랫폼과 무관한 순수 Kotlin 모듈(`core/pose`)로 분리한다. 이렇게 하면 JVM 단위 테스트로 검증할 수 있고, iOS에서는 Kotlin Multiplatform으로 재사용하거나 같은 테스트 케이스로 Swift 버전을 따로 검증할 수 있다.

## 11. 리스크 및 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 알람이 안 울림 (OS 배터리 정책) | 치명적. 앱 신뢰도 붕괴 | 플랫폼별 정확한 알람 API 사용, 제조사별 가이드, 알람 작동 자가 진단 기능 |
| 어두운 방에서 인식 실패 | 알람을 못 꺼서 짜증, 앱 삭제 | 화면 조명, 토치, 불 켜기 안내, 쉬움 난이도, 대체 해제 수단 |
| 좁은 공간이라 전신이 안 잡힘 | 인식 실패 | 거치 가이드, 광각 카메라 우선 사용, 스쿼트는 상반신+무릎만으로 판정하는 모드 검토 |
| 부상 위험 (잠결에 운동) | 사용자 안전, 법적 이슈 | 온보딩에 건강 주의 문구, 기본 횟수는 낮게, 대체 저강도 미션 |
| 카메라 사용에 대한 프라이버시 우려 | 설치 거부 | 온디바이스 처리와 미저장 원칙을 명확히 고지, 네트워크 권한 최소화 |
| 긴급 해제 남용 | 핵심 가치 훼손 | 해제 절차를 번거롭게 만들고, 사용 횟수를 통계에 표시 |
| iOS 제약 | 동일한 경험 제공 불가 | AlarmKit 활용, Android 우선 출시 |
