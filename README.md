# FitWake

푸시업이나 스쿼트를 해야 꺼지는 알람 앱. 기획 문서는 [docs/PRD.md](docs/PRD.md)에 있다.

## 진행 상황

| 단계 | 내용 | 상태 |
|---|---|---|
| M0 | 카메라 운동 인식 (푸시업·스쿼트 카운트) | 구현, 실기기 검증 전 |
| M1 | 알람 코어 (CRUD, 정확한 예약, 잠금 화면 알람, 재부팅 대응) | 구현, 실기기 검증 전 |
| M2 | 온보딩, 카운트다운, 랜덤·저강도 미션, 폰 흔들기 방지, 플래시, 음성 안내 | 구현, 실기기 검증 전 |
| M3 | 기상·운동 기록, 연속 기상 일수, 주/월 통계, 캘린더 | 구현, 실기기 검증 전 |
| + | 스누즈(미니 미션), 기상 재확인, 새 알람 기본 미션, 영어 지원 | 구현, 실기기 검증 전 |
| M4 | 베타 테스트 → 인식 기준값 튜닝 | 실기기 필요 |
| M5 | Play 스토어 출시 | 예정 |

## 구조

```
core/pose/    반복 카운터, 미션 진행(카운트다운·폰 움직임 감지) (순수 Kotlin, JVM 테스트)
core/alarm/   알람 모델, 다음 울림 시각, 볼륨 정책, 긴급 해제, 스누즈 규칙, 기록 통계 (순수 Kotlin, JVM 테스트)
app/          Android 앱 (Jetpack Compose)
  alarm/      AlarmScheduler, AlarmReceiver, BootReceiver, AlarmService(포그라운드), AlarmPlayer, WakeCheck
  data/       Room DB: 알람(AlarmRepository, 저장과 예약을 함께 처리), 기상 기록(WakeLogRepository)
  home/       알람 목록, 다음 알람까지 남은 시간, 권한 안내
  edit/       알람 편집 (시간, 요일, 미션, 알람음, 진동, 미리 해보기)
  ringing/    잠금 화면 위 알람 화면 → 미션 → 해제
  mission/    CameraX + ML Kit 포즈 인식 미션 화면
  onboarding/ 첫 실행 안내: 소개 → 권한 → 제조사 배터리 설정 → 스쿼트 3회 체험
  stats/      연속 기상 일수, 이번 주/달 운동량, 평균 해제 시간, 달력, 최근 기록
  settings/   새 알람 기본 미션, 권한 상태, 안내 다시 보기
```

## 알람이 울리는 흐름

1. `AlarmScheduler`가 `AlarmManager.setAlarmClock`으로 예약한다 (도즈 모드에서도 정시에 울림)
2. 정시에 `AlarmReceiver`가 `AlarmService`(포그라운드 서비스)를 시작한다
3. 서비스는 알람 스트림으로 소리를 내고(무음 모드 무시), 전체 화면 알림으로 `RingingActivity`를 잠금 화면 위에 띄운다
4. 반복 알람은 이 시점에 다음 회차를 예약하고, 1회용 알람은 꺼진다
5. "미션 시작"을 누르면 볼륨이 줄어들고, 60초간 한 번도 성공하지 못하면 다시 커진다
6. 목표 횟수를 채우거나, 긴급 해제 문장을 정확히 입력해야만 서비스가 멈춘다
7. 스누즈를 허용한 알람은 3회 미니 미션을 하면 5분 뒤 다시 울린다 (최대 2번)
8. 해제 결과는 기상 기록으로 저장된다. 기상 재확인을 켠 알람은 5분 뒤 "일어나 계신가요?" 알림을 보내고, 1분 안에 누르지 않으면 다시 울린다

화면을 스와이프로 닫아도 서비스는 계속 울리고, 앱을 다시 열면 알람 화면으로 돌아간다.
재부팅, 앱 업데이트, 시간·시간대 변경 때는 `BootReceiver`가 모든 알람을 다시 예약한다.

## 테스트

```bash
./gradlew :core:pose:test :core:alarm:test
```

앱은 Android Studio에서 열어 실행한다 (minSdk 29, Android 10 이상).
처음 실행하면 홈 화면에 필요한 권한(알림, 정확한 알람, 전체 화면 알림, 카메라, 배터리 최적화 제외) 안내가 뜬다.

## 미션

| 종목 | 판정 | 비고 |
|---|---|---|
| 스쿼트 | 무릎 각도 + 엉덩이 하강 | |
| 푸시업 | 팔꿈치 각도 + 몸 수평·일직선 | 측면 촬영, 쉬움에서만 무릎 푸시업 |
| 팔 올리기 | 엉덩이-어깨-손목 각도 (양팔 모두) | 부상·좁은 공간용 저강도 미션 |
| 랜덤 | 울릴 때마다 스쿼트·푸시업 중 하나 | |

- 몸이 계속 보이면 3초 카운트다운 뒤에 세기 시작한다
- 가속도계로 폰이 움직이는 걸 감지하면 카운트를 멈춘다 (폰을 들고 흔들어 속이기 방지)
- 성공할 때마다 숫자를 음성으로 읽어준다 (음성 엔진이 없으면 효과음)
- 후면 카메라를 쓸 때는 플래시를 켤 수 있다

### 실기기 확인 목록
- [ ] 1~2분 뒤 알람을 맞추고 화면을 끈 상태에서 정시에 잠금 화면 위로 뜨는지
- [ ] 무음·진동 모드, 알람 볼륨 0에서도 소리가 나는지
- [ ] 미션 중 볼륨이 줄고, 60초간 가만히 있으면 다시 커지는지
- [ ] 알람 화면을 최근 앱에서 지워도 계속 울리는지
- [ ] 재부팅 후에도 알람이 울리는지
- [ ] 반복 알람이 다음 요일로 다시 예약되는지 (상태 표시줄 알람 아이콘)
- [ ] 스쿼트 중 발 구르는 진동 때문에 "폰이 움직이고 있어요"가 잘못 뜨지 않는지 (`MotionGuard` 기준값 1.0 m/s²)
- [ ] 팔 올리기 인식 기준(보통: 어깨 각도 140°)이 자연스러운지
- [ ] 첫 실행 온보딩의 권한 버튼이 각각 맞는 설정 화면을 여는지
- [ ] 스누즈 후 5분 뒤 다시 울리고, 기록에 스누즈 횟수가 남는지
- [ ] 기상 재확인 알림을 무시하면 1분 뒤 알람이 다시 울리는지
- [ ] 기기 언어를 영어로 바꾸면 영어로 보이는지

## 남은 작업
- 실기기에서 빌드·검증 (이 저장소 코드는 Android SDK 없이 작성되어 아직 한 번도 빌드되지 않았다)
- 사진·영상 속 사람으로 속이기 방지 (PRD AC-04): 실기기 데이터로 기준을 정해야 한다
- 출시 준비: 앱 아이콘, 서명 설정, Play 정책 신고서(USE_EXACT_ALARM·전체 화면 알림은 알람 앱 용도 신고 필요), 개인정보처리방침
- DB 스키마: 첫 배포 뒤부터는 버전을 올리고 Migration 추가
- 헬스 앱 연동(ST-05), iOS 버전 (P2)
